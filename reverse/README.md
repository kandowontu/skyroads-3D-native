# SkyRoads executable reconstruction

This directory is the executable-authoritative reverse-engineering workspace.
The goal is a readable source reconstruction whose behavior can be checked
against `skyroads.exe`, not a gameplay approximation.

## What can and cannot be recovered

The MZ executable contains machine code and initialized data, not the developers'
literal `.c`/`.asm` files. Original comments, local-variable names, type names,
and source-file boundaries are absent. The reconstruction therefore uses names
supported by call sites, data flow, hardware/DOS APIs, and runtime traces.

Every recovered symbol is assigned a confidence:

- `verified`: supported by a fixed table, interrupt vector, I/O behavior, or an
  exact caller/callee contract.
- `provisional`: the routine boundary is known and the role is strongly supported,
  but some fields or branches remain unresolved.
- `unknown`: autogenerated address name only.

## Reproduce the structural analysis

```powershell
python reverse\tools\analyze_mz.py skyroads.exe
```

This writes ignored/generated analysis artifacts to `reverse/generated/`:

- `mz.json`: MZ layout, entry point, DGROUP, and relocations
- `functions.json`: recursively reachable functions and call relationships
- `calls.csv`: direct near-call/tail-call edges
- `strings.json`: code/data addresses for printable strings
- `disassembly.asm`: labeled 16-bit Capstone disassembly
- `callgraph.dot`: Graphviz call graph

`symbols.json` is the reviewed symbol database. Generated analysis never silently
upgrades confidence.

## Reproduce the Ghidra decompilation

The checked-in scripts expect Ghidra 12.1.2 and a JDK 21 installation under
`.tools/` by default; alternate locations can be supplied as parameters.

```powershell
powershell -ExecutionPolicy Bypass -File reverse\tools\run_ghidra.ps1
```

This imports the executable with Ghidra's `Old-style DOS Executable (MZ)` loader,
applies reviewed symbols (including indirect renderer entries), and exports all
discovered functions to ignored `reverse/generated/ghidra_decompiled.c`.

Manually reviewed, buildable code is kept in `reverse/reconstructed/`; generated
decompiler output is never treated as recovered source by itself.

## Capture and compare the DOS gameplay oracle

The trace builder creates a separately named, generated `SKYTRACE.EXE`; it never
modifies `skyroads.exe`. The probe follows the original demo input and records
the executable's state at the end of each gameplay tick plus its filtered sound
effect calls. DOSBox-X simultaneously records the executable's effective OPL2
register stream in DROv2 format.

```powershell
.\reverse\tools\capture_dos_oracle.ps1 -TimeLimitSeconds 30
cmake -S reverse\reconstructed -B reverse\generated\reconstructed-build -G Ninja
cmake --build reverse\generated\reconstructed-build
ctest --test-dir reverse\generated\reconstructed-build --output-on-failure
```

`recovered_dos_oracle` compares 1,702 44-byte state records and 51 sound events
against the reviewed C reconstruction. `recovered_dos_opl_oracle` compares 1,241
effective register changes produced by 8,510 calls of the original 180 Hz OPL
scheduler. The generated oracle files live under
`reverse/generated/oracle-run/`.

The companion framebuffer probe preserves the original VGA renderer and records
all 1,702 indexed gameplay frames from the original demo:

```powershell
.\reverse\tools\capture_dos_frame_oracle.ps1
```

`skyroads_frame_oracle_tests` compares all 108,928,000 captured pixel bytes with
the native host. It also checks selected mutable TREKDAT records, the generated
ship mask, and the chosen car frame. The full sequence currently matches
byte-for-byte.

Two controlled hardware-boundary probes cover the remaining active VGA/input
paths:

```powershell
.\reverse\tools\capture_dos_palette_oracle.ps1
.\reverse\tools\capture_dos_input_oracle.ps1
```

The palette comparator finds every one of the 635 distinct DAC states observed
in the wall-clock-driven DOS run byte-for-byte and in order among the native
logical fade steps. The input comparator exhausts all 2,048 keyboard masks plus
648 joystick and 512 ordered mouse vectors against `1000:074C`.

## Verified executable layout

- File size: 30,472 bytes; no overlay
- MZ header: 512 bytes
- Load module: 29,960 bytes
- Entry: `CS:IP = 0000:60D0`
- Initial stack: `SS:SP = 1183:0800`
- DGROUP relative paragraph: `066E`
- Relocations: `0000:3AAE` and `0000:60D1`
- Game `main`: `0000:01B8`, called after Borland CRT initialization

The startup shape is consistent with the Borland/Turbo C DOS runtime: it sets
DGROUP, checks the DOS/CPU environment, resizes the PSP allocation, constructs
`argc/argv`, clears BSS, calls the game entry, and exits through INT 21h/4Ch.

## Reconstruction order

1. Separate Borland runtime/library functions from game-owned code.
2. Recover game startup and asset load/error paths from `game_main`.
3. Recover main state dispatch and the 180 Hz interrupt-owned state.
4. Recover exact road rendering from dispatch handlers and `TREKDAT` primitives.
5. Recover fixed-point physics/collision and demo input.
6. Recover PC-speaker/Sound Blaster/OPL scheduling.
7. Translate verified routines into `reverse/reconstructed/` with equivalence tests.

The reviewed reconstruction currently covers the complete VGA road descriptor
walk, ship occlusion and road shadow, fixed-point gameplay/collision core,
gameplay dashboard, palette composition, shipped LZS/CMAP/PICT/ANIM/DAT resource
formats, menu/intro/demo/run-level control flow, PC-speaker/PCM effects, and the
full interrupt-driven OPL event scheduler. Gameplay state, filtered effect
events, effective OPL register changes, and every full VGA gameplay framebuffer
in the original demo now have executable-authoritative DOS oracles. The native
VGA renderer reproduces the executable's persistent delta-transfer buffer and
matches that complete sequence byte-for-byte. Palette and all non-demo input
branches now also have executable-authoritative probes. The legacy EGA
compatibility branch remains documented in the disassembly and symbol map but
is intentionally outside the native port's scope.
